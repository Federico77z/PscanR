# PscanR 0.99.0

- Add `ps_hit_score_plot()`, which plots each promoter's best hit by position and by score together. A positional profile alone cannot say whether a concentration is built from strong sites or marginal ones. Points are split into three bands by the background mean and one standard deviation above it -- the same thresholds `st` names elsewhere -- and a `PSMatrixList` is drawn as panels sharing both axes.
- Estimate hit-position and distance densities on their bounded interval. `stats::density()` assumes an unbounded quantity, so it drew the curve up to three bandwidths past the end of the scanned region and let roughly 9 % of the probability mass escape across the edges, depressing the estimate exactly where positional signal is usually read. `ps_density_plot()` and `ps_density_distances_plot()` gain a `window` argument that corrects the estimate by reflection; without it the curve is merely clipped to the observed range, since the sample extremes are not boundaries. The reflecting bounds are the positions a hit can be *reported* at, which stop `ncol(pfm) - 1` short of the end of the window because a hit is recorded at the start of the motif.
- Add a `bins` argument to both density plots, drawing the same values as a binned profile behind the curve. Heights are on the density scale, so bars and curve share one axis with no secondary axis and no rescaling. Carrying no bandwidth and no boundary assumption, the bars show what the smoothing is doing -- on real data the default bandwidth can halve the height of a narrow peak.
- Report the number of promoters a distance distribution was computed from in the title of `ps_density_distances_plot()`. A distance needs a retained hit for both motifs, so the plot can rest on far fewer promoters than were scanned, and the thresholds change that count by several fold.
- Document that `ps_hits_oligo()` and the `OLIGO` column of `ps_hits_table()` return the forward strand of the promoter whatever strand the motif matched on, as in the original Pscan implementation. A reverse-strand hit reads as the motif only after its oligo is reverse-complemented, which is easy to mistake for a scanning error.
- Add `ps_motif_barplot()`, which draws the highest ranking motifs of a scan as horizontal bars. Ranking direction and scale follow from the chosen statistic: `ZSCORE`, `FG_AVG` and `BG_AVG` rank downwards and are plotted as they are, while `P.VALUE` and `FDR` rank upwards and are plotted as -log10. Bars can be coloured by any grouping, and `group = "class"` derives the structural class of the factor without further input.
- Add `ps_motif_class()`, which reports the structural class of each motif. The class is read from the `matrixClass` slot that `PSMatrix` inherits from `PFMatrix`, so it survives scanning and is available from a scan result without consulting JASPAR again. This is not reachable through `tags(x)$class`, which is `NULL` for every JASPAR matrix in every release.
- Redraw `ps_density_plot()` and `ps_density_distances_plot()` with `ggplot2`. Both now return a `ggplot` object instead of drawing as a side effect, so figures can be restyled, faceted or saved by the caller, and all the plotting functions except the two `pheatmap` heatmaps now behave the same way. The curves themselves are unchanged: the plotted grid is the one `stats::density()` already computed, not a recomputed `geom_density()`. Code that wrapped these calls in a graphics device must now use `ggplot2::ggsave()` or print the returned object.
- Keep the mode label of both density plots inside the panel. It was previously always written to the right of the mode line, and clipped whenever the mode fell near the end of the range.
- Correct the documented return value of `ps_density_plot()`, which claimed to return a plot while returning `NULL`.
- Fix `ps_hitpos_map()` indexing the columns of the position matrix with a vector of result-table row numbers. The two coincide only while the FDR-filtered rows happen to be the leading ones, which is true of a Benjamini-Hochberg ordering but is not a property to rely on.
- `ggplot2` is now a hard dependency, and `graphics` is no longer used.
- Resolve transcript identifiers according to the scheme they belong to, instead of assuming RefSeq. A trailing `.N` is a release *version* in RefSeq (`NM_000546.6`) but a *splice variant* in TAIR (`AT1G01110.2`), and treating the second like the first merged distinct Arabidopsis transcripts onto their shared gene. The new registry recognises `refseq` (human, mouse, Drosophila), `sgd` (yeast) and `tair` (Arabidopsis), detects the scheme automatically, reports what it detected, and falls back to a lossless `generic` scheme with a warning when identifiers are unrecognised or mixed.
- Fix `pscan_fullBG()` returning the wrong transcript. It stripped both the query and the background legend before matching, so on Arabidopsis a request for `AT1G01110.2` could silently return the hits stored for `AT1G01110.1`, which usually has a different TSS. Matching is now scheme-aware, and an identifier that is ambiguous within the background raises a warning naming it instead of resolving to the first match.
- Make `ps_select_promoters()` deterministic. Candidate promoters are no longer discarded before ranking — on the TAIR9 background that silently dropped 9.1% of promoters — and selection now uses a total order, so the result no longer depends on the order promoters were supplied. Reversing the Arabidopsis promoter set previously changed the chosen transcript for 263 of 2238 genes; it now changes none, and the primary `.1` gene model is selected for every gene that has one. RefSeq selections are unchanged.
- Rename the RefSeq-specific vocabulary to neutral terms: the `refseq_col` argument becomes `transcript_col`, and the mapping columns `refseq_id`, `refseq_clean` and `refseq_type` become `transcript_id`, `transcript_base` and `transcript_class`. `sequence_names` gains the values `"gene_transcript"` and `"transcript"`, which use the full promoter identifier rather than a stripped one. This is a breaking change with no aliases.
- Report how each promoter was chosen. The mapping gains `scheme`, `suffix_role`, `n_candidates` and `decided_by` columns, `selection_source` names the rule that actually applied (`"TAIR primary model"`, `"SGD single transcript"`, `"RefSeq NM"`), unmapped genes are carried in `attr(mapping, "ps_unmapped_genes")`, and the new `ps_selection_summary()` condenses all of it into a reviewable table.
- Exclude RefSeq protein accessions (`NP_`, `XP_`) from promoter selection. OrgDb `REFSEQ` queries return them alongside mRNAs, where they were previously ranked as ordinary transcript candidates.
- `mode = "select"` now fails with an explanatory error outside the RefSeq scheme rather than silently degrading to a "RefSeq fallback" for identifiers that are not RefSeq at all.
- Compute the motif enrichment p-value as an exact upper normal tail with `pnorm(z, lower.tail = FALSE)` instead of `1 - pnorm(z)`. The previous formulation saturated at 1.11e-16 and returned exactly 0 for z-scores above roughly 8.3, so the most strongly enriched motifs could not be ranked and their FDR values collapsed to 0. Z-scores, hit scores, positions, strands and oligos are unchanged. This removes the package's only use of `BSDA`, which is no longer a dependency.
- Optimize internal sequence scanning function `.ps_scan_s` using raw byte conversion and vectorized matrix-based scoring.
- Hoist the per-motif forward/reverse-complement score matrices out of `.ps_scan_s` so they are built once per motif and reused across all sequences.
- Add a batched, encode-once scanning fast path: sequences are encoded to integer codes once per analysis (reused across all motifs) and all equal-length sequences are scored against each motif with vectorised matrix operations, with the per-sequence `.ps_scan_s` kept as a fallback for unequal-length input. Results are bitwise identical to the previous implementation.
- Accelerate unambiguous, equal-length sequence sets further with Biostrings' vectorised PWM scoring primitive, while retaining the bounded-memory R scanner for ambiguous or large inputs. Repeated 1000-promoter benchmarks remained exactly identical to the saved reference results.
- Score soft-masked (lower-case) bases as their upper-case equivalent, and return `NA` (instead of `-Inf` or an error) for sequences shorter than the motif or with no scorable window, so degenerate sequences no longer corrupt the foreground/background averages.
- Add regression tests for the sequence scanning kernel.
