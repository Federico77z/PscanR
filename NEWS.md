# PscanR 0.99.0

- Drop what the vignette reorganisation orphaned. `inst/extdata/GeneTranscript_ids.rds` and `inst/extdata/transcripts.rds` existed only for the ENSEMBL and GENCODE identifier-conversion recipes, which the concepts vignette no longer carries, and `inst/scripts/transcripts.R` generated the second of them. `biomaRt`, `rtracklayer`, `org.Dm.eg.db` and `dplyr` leave `Suggests` with them, since nothing in the package now loads any of the four. `inst/examples/Examples.Rmd` goes as well, with `inst/extdata/liver.txt`, which fed nothing else. It dated from 2022, was referenced by nothing and built by nothing, so no check had ever run it: it pointed at a vignette that no longer exists and its last chunk assigned to a `::` call, which is not valid R.
- Stop returning a cached select-transcript table that the package can no longer read. `ps_load_select_transcripts()` handed back whatever `readRDS()` yielded, and the columns it writes were renamed when transcript identifiers stopped being assumed to be RefSeq (`refseq_id`/`refseq_clean`/`select_gene_symbol` became `transcript_id`/`transcript_base`/`gene_symbol`). A cache written before that change was therefore returned intact and rejected much later, inside `ps_select_promoters()`, as a table with no `transcript_base` or `transcript_id`, with nothing to connect the error to its cause; and because the cache never expired, the failure was permanent for anyone who had run an earlier version. The cached object is now checked before it is used, and an unusable one is reported and downloaded again rather than returned.
- Fail where the cause is when a UCSC track cannot be read. `.ps_ucsc_track_by_chrom()` turned a failed request into a silently dropped chromosome and a wholly failed download into an empty `data.frame()`, which surfaced as `arguments imply differing number of rows: 0, 1` from an unrelated line. Each request is now reported with its track and chromosome, an empty or absent table is an error, and the fields each caller reads are checked as they arrive, so a renamed UCSC column is caught where it happens instead of reading as `NULL`.
- Rebuild the input half of the concepts vignette around the simple case. It loaded a list of transcripts, converted them to genes and converted them back, so the shortest path was never shown and no chunk in the vignette ever ran `pscan()`. It now scans a transcript list directly, matching promoters with one explicit substitution, and reports the result: the bundled NRF1 targets return NRF1 as the top motif at Z = 17.1. Choosing one promoter per gene follows as a separate problem, with `ps_select_promoters()` motivated by the fact that a gene list does not determine a promoter set.
- Rename `PscanFiltered()` to `pscan_filtered()`. Every other analysis entry point of the package is snake_case, and this one was not. The package has never been released, so the old name is removed outright rather than deprecated: there is no alias and no shim.
- Give the concepts vignette the two steps it was missing. *PscanR Concepts and Input Preparation* explained what a background is without saying how to obtain one, and promised a `DNAStringSet` built from identifiers without ever reaching a sequence. It now retrieves a precomputed background with `generate_psmatrixlist_from_background()`, naming the four things that identify one and the ExperimentHub-then-Zenodo route it resolves through, and it carries a worked example from RefSeq identifiers to promoter sequences through `ps_select_promoters()`, ending in the foreground `pscan()` takes. The file is renamed `PscanR_concepts_and_input.Rmd` to match its title.
- Correct the `BPPARAM` recommendation. It advised `SerialParam()` for reproducibility, which is not a reason to choose it: a scan on N workers is byte-identical to a scan on one. Debugging is the remaining justification, and is now the one given.
- Re-save the bundled `.rds` under `inst/extdata/` with xz compression, and number the sections of `PscanRQuickOverview.Rmd` from one rather than from `0.1`. The objects are unchanged; the recompression alone takes the source tarball from 5,188,382 bytes to 4,512,271, back under the 5,000,000-byte Bioconductor limit that the previous release candidate exceeded.
- Reorganise the vignettes around three worked examples. `PscanR_Mouse_HD_Retina.Rmd`, `PscanR_Arabidopsis_BPC.Rmd` and `PscanR_Custom_Background.Rmd` are new, and the fixtures they render from now ship under `inst/extdata/vignettes/`, so the collection builds from an installed package instead of from a working directory outside it. `Background_generation.Rmd` is superseded by the custom-background vignette and has been removed. `Scanning_performance.Rmd` and `Execution_time_cores.Rmd` have been removed as well: both were benchmark reports of one machine rather than usage documentation, and the actionable half of the second -- which `BPPARAM` to choose, and why more cores can be slower on a small foreground -- is now stated as a recommendation in the concepts vignette, with the two worked examples supplying measured timings. `PscanR_concepts_and_input.Rmd` is retitled *PscanR Concepts and Input Preparation* and cut to the two things it alone carried, the conceptual orientation and the identifier-conversion recipes for ENSEMBL, RefSeq, GENCODE and SGD; everything else in it had come to duplicate the worked examples. `PscanRQuickOverview.Rmd` grows from thirteen functions to twenty-two, and `inst/extdata/promoters.rds` goes with the vignette that was its last reader.
- Fix the `output:` block of `PscanRQuickOverview.Rmd` and `PscanR_concepts_and_input.Rmd`, where `toc` and `toc_depth` were indented as siblings of `BiocStyle::html_document` rather than as its options. Both were silently ignored, so those vignettes rendered without a table of contents.
- Record that a background artefact's `artifact_sha256` is a *same-platform* guarantee. Rebuilding the catalogued sacCer3 `950u_50d` background on Apple Silicon reproduces the promoter set exactly -- 6,639 transcripts, 6,571 distinct promoters, the same promoter hash -- and every one of the 183 matrices agrees with the x86-64 build to ten decimal places, but the file is not byte-identical: 138 of 183 lines differ, `BG_STDEV` by up to 524 ulps and `BG_MEAN` by up to 11. `ps_build_bg()` reaches log-odds through `colSums()` and `log()`, whose last place depends on the width of a `long double` and on the libm, so the scoring matrix differs before a single window is scored. Nothing downstream can see it -- the difference is at the fourteenth significant digit and beyond -- but the checksum can, so treat it as a download integrity check rather than a rebuild-anywhere check. The comment at `ps_write_bg_to_file()` now records why widening the text format to 17 significant digits is rejected rather than deferred: it would round-trip a platform-dependent double faithfully and make cross-platform rebuilds diverge more, not less.
- Refuse to apply a background table that disagrees with the stored background scan. `ps_build_bg_from_table()` -- and so `ps_retrieve_bg_from_file()` -- replaces `BG_SIZE`, `BG_MEAN` and `BG_STDEV` while leaving the per-promoter hits and the `transcriptIDLegend` as they came in, so a file written from a *different* background (another window, another organism, another annotation) produced an object whose statistics described one promoter universe and whose hits and legend described another. `pscan_fullBG()` then read it as a background and computed z-scores from the second against the first, silently and with a different motif ranking. Until the legend was carried through rebuilds this could not be acted on, because the object came back without a legend and `pscan_fullBG()` refused it -- an accidental safety net that the fix removed. `ps_bg_size()` is set to the number of hits retained when a background is scanned, so the two are equal by construction and the disagreement is free to detect; it is now an error naming both counts. Note that this is a necessary condition and not a sufficient one: two different promoter sets of the same size still pass.
- Carry the `transcriptIDLegend` through every rebuild of a `PSMatrixList`. The legend maps each transcript of the organism onto the representative kept when duplicate promoters were collapsed, and it is what makes an object a *full* background; but it is a slot of the list, and every function that rebuilt one -- `ps_build_bg_from_table()` and so `ps_retrieve_bg_from_file()`, `pscan()`, `pscan_fullBG()`, `pscan_filtered()`, and the `PFMatrixList`/`PSMatrixList` coercion -- dropped it. A full background therefore survived only the one function that created it: writing it out and reading it back silently degraded it into an ordinary one, and `pscan_fullBG()` could not be chained because its own result was no longer a full background. The exported `PSMatrixList()` constructor was the root cause: it declared and documented a `transcriptIDLegend` argument and never passed it on, so no rebuilt object could carry a legend at all. It now does, and every rebuild propagates the legend of the object that describes the promoter universe -- `background` rather than `Jmatrix` in `pscan_filtered()`. `ps_build_bg()` is the one exception, and deliberately: its output must describe the sequences it was just given, so it derives the legend from them when `fullBG = TRUE` and leaves it empty otherwise, exactly as before.
- Test `pscan_fullBG()` for a background scan instead of for a legend. It used a non-empty `transcriptIDLegend` as a proxy for "this object holds per-promoter background hits", which stops discriminating once every object carries a legend: a `pscan()` result would have passed the guard and then been read as a background, answering with foreground hits over a subset instead of background hits over the universe. The two conditions are now checked separately and reported separately.
- Document that a full background is persisted with `saveRDS()` / `readRDS()`, and that the `.txt` format written by `ps_write_bg_to_file()` carries only the background size, mean and standard deviation of each matrix -- enough for `pscan()`, not enough for `pscan_fullBG()`.
- Remove `ps_density_distances_plot()`. It drew the distribution of distances between the best hits of two matrices, but PscanR keeps only one hit per promoter per matrix, so a promoter carrying several sites contributes a single pair and the distance recovered is between two winners rather than between two members of a composite element. Applied to the cases most likely to show spacing -- interferon factors on co-regulated promoters, and NF-Y against seven reported partners over ChIP-defined promoters, at two score thresholds and two promoter windows -- it returned either a spike at zero that reflected the two matrices matching the same DNA, or a distribution indistinguishable from random promoters. The function had no case in which it said anything, and the internal `.ps_hit_distances()` goes with it.
- Warn when the foreground is more than a tenth of the background. The Pscan z-score is `sqrt(n)` times the standardised difference in mean score, so it grows with the size of the foreground and not only with the strength of the signal; and since the background is every promoter, a foreground of `n` out of `N` is compared against a set that largely consists of itself, which shrinks the measured difference by `1 - f` with `f = n / N`. At `f = 0.48` the two effects together turned a real ordering of motifs into an artefact: matrices that ranked 107th and 116th of 746 came first and third once the same comparison was made at `f = 0.03`. Neither effect is visible in the reported number, so `pscan()`, `pscan_fullBG()`, `pscan_filtered()` and `ps_results_table()` now say so, with the counts and the attenuation factor. Set `options(PscanR.foreground.max_fraction = )` to move the threshold, or `Inf` to silence it.
- Keep `ps_hit_score_plot()` readable at large scan sizes. Point opacity and size were fixed at values that suit a few hundred promoters; at twenty thousand each panel saturated into three solid blocks of colour and carried no information. Both are now scaled from the number of promoters, and can be set directly through the new `alpha` and `size` arguments. Nothing is subsampled and nothing is binned, so the figure still means one point per promoter.
- Strip surrounding whitespace from the class `ps_motif_class()` reports. JASPAR 2020 gives the IRF3, IRF4 and IRF5 matrices `"Tryptophan cluster factors "` with a trailing space, which split that class into two grouping levels: `ps_motif_barplot(group = "class")` drew two legend entries with the same visible label and coloured 3 of the 41 members separately from the rest. A class that is whitespace only is now reported as `"Unclassified"`, as the empty string already was.
- Add `ps_hit_score_plot()`, which plots each promoter's best hit by position and by score together. A positional profile alone cannot say whether a concentration is built from strong sites or marginal ones. Points are split into three bands by the background mean and one standard deviation above it -- the same thresholds `st` names elsewhere -- and a `PSMatrixList` is drawn as panels sharing both axes.
- Estimate hit-position and distance densities on their bounded interval. `stats::density()` assumes an unbounded quantity, so it drew the curve up to three bandwidths past the end of the scanned region and let roughly 9 % of the probability mass escape across the edges, depressing the estimate exactly where positional signal is usually read. `ps_density_plot()` gains a `window` argument that corrects the estimate by reflection; without it the curve is merely clipped to the observed range, since the sample extremes are not boundaries. The reflecting bounds are the positions a hit can be *reported* at, which stop `ncol(pfm) - 1` short of the end of the window because a hit is recorded at the start of the motif.
- Add a `bins` argument to `ps_density_plot()`, drawing the same positions as a binned profile behind the curve. Heights are on the density scale, so bars and curve share one axis with no secondary axis and no rescaling. Carrying no bandwidth and no boundary assumption, the bars show what the smoothing is doing -- on real data the default bandwidth can halve the height of a narrow peak.
- Document that `ps_hits_oligo()` and the `OLIGO` column of `ps_hits_table()` return the forward strand of the promoter whatever strand the motif matched on, as in the original Pscan implementation. A reverse-strand hit reads as the motif only after its oligo is reverse-complemented, which is easy to mistake for a scanning error.
- Add `ps_motif_barplot()`, which draws the highest ranking motifs of a scan as horizontal bars. Ranking direction and scale follow from the chosen statistic: `ZSCORE`, `FG_AVG` and `BG_AVG` rank downwards and are plotted as they are, while `P.VALUE` and `FDR` rank upwards and are plotted as -log10. Bars can be coloured by any grouping, and `group = "class"` derives the structural class of the factor without further input.
- Add `ps_motif_class()`, which reports the structural class of each motif. The class is read from the `matrixClass` slot that `PSMatrix` inherits from `PFMatrix`, so it survives scanning and is available from a scan result without consulting JASPAR again. This is not reachable through `tags(x)$class`, which is `NULL` for every JASPAR matrix in every release.
- Redraw `ps_density_plot()` with `ggplot2`. It now returns a `ggplot` object instead of drawing as a side effect, so figures can be restyled, faceted or saved by the caller, and all the plotting functions except the two `pheatmap` heatmaps now behave the same way. The curve itself is unchanged: the plotted grid is the one `stats::density()` already computed, not a recomputed `geom_density()`. Code that wrapped this call in a graphics device must now use `ggplot2::ggsave()` or print the returned object.
- Keep the mode label of `ps_density_plot()` inside the panel. It was previously always written to the right of the mode line, and clipped whenever the mode fell near the end of the range.
- Correct the documented return value of `ps_density_plot()`, which claimed to return a plot while returning `NULL`.
- Fix `ps_hitpos_map()` indexing the columns of the position matrix with a vector of result-table row numbers. The two coincide only while the FDR-filtered rows happen to be the leading ones, which is true of a Benjamini-Hochberg ordering but is not a property to rely on.
- `ggplot2` is now a hard dependency, and `graphics` is no longer used.
- Resolve transcript identifiers according to the scheme they belong to, instead of assuming RefSeq. A trailing `.N` is a release *version* in RefSeq (`NM_000546.6`) but a *splice variant* in TAIR (`AT1G01110.2`), and treating the second like the first merged distinct Arabidopsis transcripts onto their shared gene. The new registry recognises `refseq` (human, mouse, Drosophila), `sgd` (yeast) and `tair` (Arabidopsis), detects the scheme automatically, reports what it detected, and falls back to a lossless `generic` scheme with a warning when identifiers are unrecognised or mixed.
- Fix `pscan_fullBG()` returning the wrong transcript. It stripped both the query and the background legend before matching, so on Arabidopsis a request for `AT1G01110.2` could silently return the hits stored for `AT1G01110.1`, which usually has a different TSS. Matching is now scheme-aware, and an identifier that is ambiguous within the background raises a warning naming it instead of resolving to the first match.
- Make `ps_select_promoters()` deterministic. Candidate promoters are no longer discarded before ranking — on the TAIR9 background that silently dropped 9.1% of promoters — and selection now uses a total order, so the result no longer depends on the order promoters were supplied. Reversing the Arabidopsis promoter set previously changed the chosen transcript for 263 of 2238 genes; it now changes none, and the primary `.1` gene model is selected for every gene that has one. RefSeq selections are unchanged.
- Rename the RefSeq-specific vocabulary to neutral terms: the `refseq_col` argument becomes `transcript_col`, and the mapping columns `refseq_id`, `refseq_clean` and `refseq_type` become `transcript_id`, `transcript_base` and `transcript_class`. `sequence_names` gains the values `"gene_transcript"` and `"transcript"`, which use the full promoter identifier rather than a stripped one. This is a breaking change with no aliases.
- Report how each promoter was chosen. The mapping gains `scheme`, `suffix_role`, `n_candidates` and `decided_by` columns, `selection_source` names the rule that actually applied (`"TAIR primary model"`, `"SGD single transcript"`, `"RefSeq NM"`), unmapped genes are carried in `attr(mapping, "ps_unmapped_genes")`, and the new `ps_selection_summary()` condenses all of it into a reviewable table.
- Exclude RefSeq protein accessions (`NP_`, `XP_`) from promoter selection. OrgDb `REFSEQ` queries return them alongside mRNAs, where they were previously ranked as ordinary transcript candidates.
- `mode = "select"` now fails with an explanatory error outside the RefSeq scheme rather than silently degrading to a "RefSeq fallback" for identifiers that are not RefSeq at all.
- Compute the motif enrichment p-value as an exact upper normal tail with `pnorm(z, lower.tail = FALSE)` instead of `1 - pnorm(z)`. The previous formulation saturated at 1.11e-16 and returned exactly 0 for z-scores above roughly 8.3, so the most strongly enriched motifs could not be ranked and their FDR values collapsed to 0. Z-scores, hit scores, positions, strands and oligos are unchanged. This removes the package's only use of `BSDA`, which is no longer a dependency.
- Optimize internal sequence scanning function `.ps_scan_s` using raw byte conversion and vectorized matrix-based scoring.
- Hoist the per-motif forward/reverse-complement score matrices out of `.ps_scan_s` so they are built once per motif and reused across all sequences.
- Add a batched, encode-once scanning fast path: sequences are encoded to integer codes once per analysis (reused across all motifs) and all equal-length sequences are scored against each motif with vectorised matrix operations, with the per-sequence `.ps_scan_s` kept as a fallback for unequal-length input. Results are bitwise identical to the previous implementation.
- Accelerate unambiguous, equal-length sequence sets further with Biostrings' vectorised PWM scoring primitive, while retaining the bounded-memory R scanner for ambiguous or large inputs. Repeated 1000-promoter benchmarks remained exactly identical to the saved reference results.
- Score soft-masked (lower-case) bases as their upper-case equivalent, and return `NA` (instead of `-Inf` or an error) for sequences shorter than the motif or with no scorable window, so degenerate sequences no longer corrupt the foreground/background averages.
- Add regression tests for the sequence scanning kernel.
